# Dance Over Sky

一个俯视「沙盘视角」的 2D 空战小游戏：不写死「按键直接转向」，而是用矢量实时算
推力、升力、阻力与过载，让飞机按力学规律飞。

> 「战列舰侧舷互射导弹」是本项目对这一玩法的诙谐说法：双方隔着几十公里互相丢中距弹
> （超视距对射）。它不是独立模式，也不是严谨的学术概念，就是现代空战的一种戏称。

当前状态：里程碑 **M1** 已完成，25 项验收测试通过。已经可以跑起来——一架玩家机
（Q/E 转向）+ 一架只会直线飞的敌机，外加一个显示攻角与过载的 HUD。


## 游戏简介

核心想法是「能飞得讲道理」。大多数 2D 空战小游戏里，机头指向就是速度方向，拉力
多大就转多快；这个项目反过来，把飞机当成一个有质量、有气动特性的物体：

* 机头指向与速度方向是两个独立的状态，两者的夹角就是**攻角**；
* 攻角决定升力，升力垂直于速度，用它把航迹掰弯；
* 拉杆掉速（诱导阻力），所以存在能量与速度的取舍；
* 过载既受结构限制（9g），也受失速限制，低速时够不到 9g。

视角是俯视平面沙盘，所以**不做高度、不做重力**：在这个二维世界里，「升力」就是
水平面内的向心力，「过载」是水平面内的法向过载。这是刻意选择，不是遗漏。

初始机型以 F-16 为蓝本，导弹计划以 AIM-120 为蓝本。后续视情况加入近距机炮缠斗
（也就是「骑士机炮对决」）与多机型。


## 快速开始

需要 Python 3.10+（开发使用 3.13）与 pygame 2.x：

```bash
pip install pygame
python dance_over_sky.py
```

操作：

| 按键 | 作用 |
| --- | --- |
| `Q` / `E` 或 `←` / `→` | 偏航（左转 / 右转） |
| `Z` / `X` | 拉近 / 拉远（1~60 m/px） |
| `G` | 开关背景网格 |
| `F3` | 开关 HUD 与调试线 |
| `Esc` | 退出 |

HUD 上可以看到速度、机头指向、速度方向、攻角（含当前允许的上限）、过载，
以及升力 / 阻力 / 推力三个分量。调试线里黄色是机头指向，青色是速度方向，
两条线的夹角就是攻角。

运行验收测试：

```bash
python -m unittest discover -s tests -t .
```


## 游戏机制

### 坐标与角度约定

世界坐标与屏幕坐标都是 x 向右、y 向下（pygame 默认）。**世界坐标一律用米**，
像素只属于渲染层。

`heading`（机头指向 / 速度方向角）以 +x 为 0°，顺时针为正，范围 (-180, 180]：

| heading | 0° | 90° | -90° | 180° |
| --- | --- | --- | --- | --- |
| 方向 | 右 | 下 | 上 | 左 |

攻角 `alpha = heading - velocity_heading`，正值表示机头偏向速度方向的顺时针侧。

这里有个容易踩的坑：pygame 的 `Vector2.angle_to()` 返回的是「从 self 转到 other」
的角度，符号与 `heading` 相反（`v.angle_to(Vector2(1,0)) == -heading(v)`）。
初版就在此栽过——机头与速度同向朝上飞时算出了 180° 攻角，凭空多出约 2e6 N
（约 21g）的假力。现在统一用 `angles.vector_heading_deg()`，并有回归测试钉住。

### 每一步都算什么

物理步长固定 **60Hz**（`dt = 1/60 s`），渲染帧率独立，用累加器补算。
所有角速度用 °/秒，禁用「°/帧」，否则改帧率就等于改物理。

1. 由 `heading` 与速度方向算出攻角；
2. 由过载上限 `n_max` 与失速上限 `cl_max` 反解当前速度下允许的最大攻角，取更严的；
3. 机头按杆量转动（°/秒），并把转动量限制到不使攻角超过上限；
4. 由攻角算升力系数 `CL`，再由动压 `q` 算升力（垂直于速度，起向心作用）与阻力；
5. 加上沿机头方向的推力，合成合力；
6. `a = F/m` 积分得到速度与位移；
7. 刷新过载，供 HUD、后续的导弹发射条件与 AI 使用。

受力公式：

```
q = 0.5 * rho * V^2                    动压（rho = 0.660，6000m 标准大气）
CL = CL_alpha * alpha                  线性升力线，超过 CL_max 按失速截断
L  = q * S * CL                        升力，垂直于速度
D  = q * S * (Cd0 + k * CL^2)          阻力，沿速度反方向；k = 1/(pi*e*AR)
T  = 沿机头方向                         本版为恒定最大推力
n  = |L| / (m * g)                     过载
```

阻力里的 `k * CL^2` 是诱导阻力。少了这一项，飞机拉 9g 不掉速，能量战就不存在了。

### 过载与攻角限制

限制不是「超了就锁死按键」，而是按物理来：先算出当前速度下要达到 `n_max` 需要多大
的升力系数，再换算成攻角上限，与失速攻角取更严的那个，然后限制机头转动不越过它。

于是速度高低会自然产生不同的限制：

* **低速**：失速限制为主，够不到 9g；
* **角点速度附近**：两者同时到达，机动性最好；
* **高速**：结构限制为主，攻角上限很小，转弯半径大。

### 相机与尺度

「1px = 10m」只是相机的默认参数，随时可缩放。相机默认跟随玩家，所以玩家固定在
屏幕中心。图标尺寸与物理尺度解耦：15m 长的飞机在 10m/px 下只有 1.5 像素，
所以图标永远按像素绘制。

这条不只是渲染细节。真实交战距离远大于屏幕——AIM-120 射程几十公里，而 10 m/px 下
屏幕只有 8×6 km。要做超视距互射，尺度方案（相机缩放 + 雷达显示）必须在武器阶段
同期定下来。

背景里有网格作位置参考：间距在世界坐标上取 50m~10km 的档位，随缩放自动切换，
每 5 格一条主线并标出公里数，原点两条轴线更亮。

### 初始机型参数

参数全部放在 `data/*.json`，加新机型不需要改代码。

| 参数 | 值 |
| --- | --- |
| 质量 | 10000 kg |
| 机翼面积 | 28 m² |
| 展弦比 / 奥斯瓦尔德效率 | 3.2 / 0.8 |
| 零升阻力系数 `Cd0` | 0.018 |
| 升力线斜率 `CL_alpha` | 4.5 /rad |
| 最大升力系数 `CL_max` | 1.5（失速攻角约 19.1°） |
| 最大过载 | 9 g |
| 最大推力 | 76000 N（推重比 0.78） |
| 杆量最大角速度 | 30 °/s |

由这组参数推导（改动参数后这些数字要同步更新）：

| 结果 | 数值 |
| --- | --- |
| 角点速度 | 约 250 m/s（失速与 9g 同时到达） |
| 250 m/s 平飞阻力 | 约 10.4 kN |
| 最大平飞速度 | 约 676 m/s（未含跨声速阻力上升） |
| 250 m/s 满攻角瞬时过载 | 约 8.8 g |
| 对应航迹角速度 | 约 20 °/s |

### 已知简化

* 没有高度、没有重力、没有三维机动（俯视沙盘的选择）；
* 失速只做截断，不模拟失速后的抖振与掉升力；
* 没有跨声速阻力上升，最大平飞速度偏高；
* 推力曲线接口已留（`thrust_curve_coeffs`），暂用恒定最大推力。


## 项目结构

```
settings.py        全局设置（步长、相机、场景）
angles.py          角度工具与全项目角度约定
aircraft_spec.py   机型参数（从 JSON 读取）
flight_model.py    点质量飞行力学（纯物理，不碰渲染、不读时钟）
camera.py          世界坐标 <-> 屏幕像素
grid.py            背景网格（位置参考）
world.py           实体集合与固定步长推进
air_object.py      实体 = 物理状态 + 图标绘制
dance_over_sky.py  主循环（固定步长累加器、输入、HUD）
data/f16.json      机型参数
images/f-16.png    机型图标（透明底）
tests/             验收测试
tools/             辅助脚本（图标转透明、无头截图）
开发计划.md         项目计划与约定，唯一事实来源
```
